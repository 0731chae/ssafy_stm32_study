## Polling/Interrupt
### polling
polling 방식은 상태를 읽기위해 계속해서 클럭을 소모함.

### interrupt
interrupt 방식은 상태가 변하면 CPU에게 직접 알려주는 방식

### 그럼 interrupt가 더 우월한 거 아님?
아니다. interrupt는 사실 일종의 서비스 중단? 이라고 볼 수 있다.

인터럽트가 들어온다면 하던 일을 멈추고 인터럽트를 먼저 처리해야한다.

만약 너가 진짜 중요한 일 하는데 스위치를 인터럽트 처리 해놨다면 인터럽트를 먼저 처리해야해서  작업이 중단됨

그리고 주기적으로 값이 변화하는 것들 예를 들어 센서로 값을 읽어오는 경우는 인터럽트로 처리하면 인터럽트 오버헤드 때문에 손해를 크게 보게 될거임

### 그렇다고 인터럽트를 안쓰는 건 말이 안됨
말 그대로다. 인터럽트를 안쓰는 건 말이 안된다. 버튼같은 경우는 어차피 사람이 1ms마다 누를 일도 없고 대개 중요한 것도 아니니까 폴링 정도로 처리해도 괜찮다. (물론 비상정지 이런건 인터럽트로 해야겠지만)

하지만 센서 같은경우 에러값을 내뿜거나, 온도가 말도 안되게 높아진다거나 등의 문제가 생긴다면 이런 비정상 동작의 경우는 해결 해야하잖아. 그러니 인터럽트를 써야함

## 상세 기술 설명내용
NVIC 은 '교통정리를 전담하는 하드웨어 컨트롤러', 스태킹(Stacking) 은 '작업 중이던 상태를 메모리에 자동 백업하는 행위', 벡터 패치(Vector Fetch) 는 '실행할 인터럽트 함수의 시작 주소를 메모리에서 가져오는 동작'을 뜻한다.

###  NVIC
Nested (중첩) : 인터럽트가 실행 중일 때 더 높은 우선순위의 긴급한 인터럽트가 들어오면, 현재 실행 중인 인터럽트를 일시 중단하고 새 인터럽트를 먼저 처리할 수 있는 구조(선점, Preemption)를 제공합니다.

Vectored (벡터형) : 과거 프로세서는 인터럽트 핀이 울리면 CPU가 소프트웨어로 "어떤 장치가 신호를 보냈는지" 모든 핀을 하나씩 조회(Polling)해야 했습니다. 반면 NVIC 은 수십 개의 인터럽트 중 누가 발생했는지 하드웨어가 즉시 식별하여, 각 장치 전용 함수(Vector)로 곧장 점프시킵니다.

### Stacking
인터럽트는 메인 코드가 실행되는 도중 언제 튈지 모르는 비동기적 사건입니다. 메인 코드가 CPU 내부 레지스터( $R0 \sim R15$ )를 한창 쓰면서 계산 중이었는데, 갑자기 인터럽트 함수가 실행되어 이 레지스터들을 덮어써 버리면 복귀했을 때 시스템이 고장 납니다.스태킹 은 인터럽트 함수로 넘어가기 직전, 현재 작업 중이던 핵심 레지스터 8개의 값을 SRAM의 스택 메모리에 자동으로 밀어 넣어(Push) 백업하는 하드웨어 동작 입니다.

하드웨어 자동 처리 : 프로그래머가 어셈블리어로 백업 코드를 짜지 않아도, Cortex-M 코어가 신호를 받자마자 클록 단위로 스스로 스택에 집어넣습니다.

기본 스택 프레임 (32바이트) : 높은 주소에서 낮은 주소로 다음 순서대로 저장됩니다.

```
[ 높은 주소 ]
  xPSR        (현재 프로그램 상태 및 플래그)
  PC          (인터럽트 끝나고 돌아갈 메인 코드의 주소)
  LR          (링크 레지스터, 함수 호출 복귀값)
  R12         (임시 레지스터)
  R3          (함수 인자/임시 값)
  R2          (함수 인자/임시 값)
  R1          (함수 인자/임시 값)
  R0          (함수 인자/임시 값) <- SP(스택 포인터)가 최종적으로 가리키는 위치
[ 낮은 주소 ]
```


### Vector Fetch
NVIC (Nested Vectored Interrupt Controller) 가 스태킹(Stacking) 과 벡터 패치(Vector Fetch) 를 버스 레벨에서 병렬로 실행하는 하드웨어 기반 아키텍처로 동작
