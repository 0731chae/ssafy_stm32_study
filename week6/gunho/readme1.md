## NVIC : 지난 5주차 내용 !
### STM32의 중단 처리 장치 NVIC(Nested Vectored Interrupt Controller)의 주요 특징
> "MCU(마이크로컨트롤러)가 여러 가지 긴급한 일(인터럽트)을 처리할 때 작업 순서와 우선순위를 정해주는 핵심 제어 센터"

* **중첩 인터럽트 지원 (Nested)**
  인터럽트를 처리하는 중(ISR 실행 중)이라도 더 높은 우선순위를 가진 인터럽트가 발생하면, 기존 처리를 잠시 멈추고 새로운 인터럽트를 먼저 처리합니다.

* **벡터 방식의 빠른 호출 (Vectored)**
  인터럽트가 발생했을 때 하드웨어적으로 벡터 테이블(Vector Table)의 주소를 직접 참조하여 해당하는 인터럽트 서비스 루틴(ISR)으로 즉시 점프합니다. CPU가 소프트웨어로 어떤 인터럽트가 발생했는지 일일이 확인할 필요가 없어 대기 시간이 매우 짧습니다.

* **우선순위 관리 (Priority Management)**
  다양한 단계의 인터럽트 우선순위(예: STM32F446 기준 16단계)를 프로그램에서 직접 설정하여 중요한 작업을 우선적으로 다룰 수 있습니다.

* **Tail-Chaining 기획**
  연속으로 발생한 인터럽트를 처리할 때 레지스터 복원 및 저장 과정을 생략하고 바로 다음 인터럽트로 넘어가 전환 지연 시간(Latency)을 최소화합니다.


* **NVIC (중첩 벡터 인터럽트 컨트롤러)**: CPU와 직접 연결되어 외부/내부 signal이 발생했을 때 작업 중인 코드를 잠시 멈추고 우선순위가 높은 작업부터 빠르게 처리해 주는 장치입니다.
* **96 maskable interrupt channels**: CPU 내부 전용 인터럽트 16개를 제외하고, 개발자가 켜고 끌 수 있는(Maskable) 주변 장치 인터럽트 신호를 최대 96개까지 관리할 수 있습니다.
* **16 programmable priority levels (4 bits)**: 인터럽트의 우선순위를 16단계로 나누어 설정할 수 있습니다. 숫자가 낮을수록 더 급한 인터럽트이며, 중요한 일이 터지면 하던 일을 멈추고 바로 넘어가게 됩니다(중첩/Nested 기능).
* **low-latency handling**: CPU 핵심 부위와 밀접하게 붙어 있어서 인터럽트 요청이 들어왔을 때 즉각적이고 매우 빠르게 반응합니다.
* **power management control**: 저전력 모드(Sleep, Stop 모드 등)에서 인터럽트가 발생했을 때 시스템을 다시 깨우는(Wakeup) 연동 제어를 담당합니다.
* **PM0214 참조**: 시스템 컨트롤 레지스터 설정이나 세부 프로그래밍 정보는 별도의 프로그래밍 매뉴얼(PM0214)을 참고하라는 안내입니다.

### 동작 흐름 예시
```text
[메인 코드 실행 중]
↓ (버튼 누름 / EXTI 발생)
[NVIC가 우선순위 및 활성화 상태 확인]
↓
[우선순위가 높으면 메인 코드 상태 자동 저장 후 ISR Jump]
↓
[인터럽트 함수(ISR) 수행]
↓
[자동 레지스터 복원 및 메인 코드로 복귀]
```


## 1. NVIC의 핵심 내부 구조 및 역할

NVIC는 ARM Cortex-M 코어 내부(Core Peripheral)에 위치하여 CPU와 직접 밀접하게 연결(Closely coupled)되어 있습니다.

### 상태 관리 레지스터 (Status Registers)
* **Enable Bit (ISER / ICER):** 해당 인터럽트를 통과시킬지(Enable) 차단할지(Disable) 결정합니다.
* **Pending Bit (ISPR / ICPR):** 인터럽트 요청 신호가 들어와 처리를 기다리고 있는지 나타냅니다.
* **Active Bit (IABR):** 해당 인터럽트가 현재 CPU에서 처리(ISR 실행) 중인지 표시합니다.

### 우선순위 판별기 (Priority Arbiter)
* STM32F446 기준 16단계(4비트)의 예외/인터럽트 우선순위(Priority Level)를 비교합니다. 숫자가 작을수록 높은 우선순위를 가집니다.

### 벡터 테이블 참조 (Vector Table Mapping)
* 각 인터럽트에 대응되는 ISR 함수 주소가 정렬된 메모리 영역(Vector Table)을 자동 탐색합니다.

## 2. 인터럽트 처리의 전체 5단계 과정

외부 핀(EXTI)이나 타이머 등 주변장치에서 시작하여 메인 코드로 복귀하기까지의 상세 단계입니다.

### ① [단계 1] 인터럽트 요청 및 검증 (Request & Arbitration)
* 주변 장치(Peripheral)에서 사건이 발생하여 인터럽트 신호를 NVIC로 전송합니다.
* NVIC는 아래 조건을 검사합니다:
  * 해당 인터럽트 채널이 Enable 상태인가?
  * 현재 실행 중인 코드/인터럽트보다 우선순위가 높은가?
* 조건이 충족되면 Pending 비트가 세팅되며 CPU 실행 권한을 획득합니다.

### ② [단계 2] 자동 상태 저장 (Hardware Stacking / Context Save)
* CPU가 인터럽트로 점프하기 전, 돌아올 위치와 연산 상태를 보존하기 위해 하드웨어가 자동으로 스택(Stack) 메모리에 주요 레지스터를 저장합니다.
* **자동으로 저장되는 레지스터 (8개):** `R0`, `R1`, `R2`, `R3`, `R12`, `LR(Link Register)`, `PC(Program Counter)`, `xPSR`
* **특징:** 소프트웨어적으로 PUSH 명령어를 실행할 필요 없이, 하드웨어가 클럭 주기 동안 자동으로 스택에 밀어 넣으므로 시간이 단축됩니다.

### ③ [단계 3] 벡터 읽기 및 ISR 점프 (Vector Fetch & Jump)
* CPU가 스택 작업을 진행하는 동안, NVIC는 벡터 테이블(Vector Table)에서 발생한 인터럽트에 해당하는 함수(ISR)의 메모리 주소를 읽어옵니다.
* PC(Program Counter)에 해당 ISR 주소가 로드되고, LR 레지스터에는 복귀 신호용 특수값인 `EXC_RETURN`이 저장됩니다.
* 해당 인터럽트의 Active 비트가 세팅되고 Pending 비트는 자동으로 해제됩니다.

### ④ [단계 4] ISR(인터럽트 서비스 루틴) 실행
* CPU가 ISR 함수 내부 코드를 실행합니다.
* (필요 시) 하드웨어에 따라 주변장치의 Pending Flag(예: `EXTI_PR` 등)를 소프트웨어 코드로 clear 해줍니다.

### ⑤ [단계 5] 자동 상태 복원 및 복귀 (Hardware Unstacking / Exit)
* ISR이 종료되면 `BX LR` (또는 `POP {PC}`) 명령어가 실행됩니다.
* 이때 LR에 들어있던 `EXC_RETURN` 값을 인지한 하드웨어가 스택에 저장해두었던 레지스터(`R0-R3`, `PC` 등)들을 자동으로 복원합니다.
* 중단되었던 원래 메인 코드나 이전 인터럽트 위치로 돌아가 정상 실행을 재개합니다.

## 3. NVIC만의 하드웨어 최적화 메커니즘

NVIC는 인터럽트 지연 시간(Latency)을 최소화하기 위해 다음과 같은 하드웨어 특화 기능을 내장하고 있습니다.

```text
[일반적인 연속 인터럽트]
ISR 1 실행 -> Unstacking(레지스터 복원) -> Stacking(레지스터 저장) -> ISR 2 실행

[Tail-Chaining 기법 적용]
ISR 1 실행 -> [Unstacking / Stacking 생략] -> ISR 2 실행 (대폭 대기시간 감소)
```
